# HavnVard 3.0.0 — first public release (20261112)

## Breaking changes
| Change | What to do |
|---|---|
| Site-specific values (hosts, database env file, NAS, agents, Telegram chat, UI links, scan mounts, report labels) moved out of the code into one site file (`havnvard_site.py`, `config/site.example.toml`). | Install `/etc/havnvard/site.toml` **before** upgrading. Without it the tools assume one machine and a local `havnvard` database. |
| `backup` exclude profiles renamed: `spark` → `ml-workstation`, `desktop-1` → `desktop-sync`; lists use `{HOME}`. | Only affects new `enroll` runs; existing devices keep their excludes file. |
| `backup` alerts: no default alertlib path. | Set `HAVNVARD_ALERTLIB_PATH`, or `[alerts] command = [...]` in `backup.toml` (new: any program, per-key cooldown). |
| `infra126` (bit-rot) defaults: only the local machine, no path exclusions. | Set `INFRA126_HOSTS_JSON` and `INFRA126_EXCLUDE_PATH_PREFIXES` in its env file. |
| `run_all_nas_shares.sh` reads the share list from `$HAVNVARD_NAS_SHARES` (default `/etc/havnvard/nas_shares.txt`). | Create that file, one share per line. |
| Database tests need `HAVNVARD_TEST_DSN` (scratch DB); they no longer use the production database. | See `tests/README.md`. |
| Removed: per-app legacy `systemd/havnvard-restic-*` units, `infra126/deploy/*.sh` (they disabled timers and rsync --delete'd a live directory), the built wheel, egg-info and stale manifests; the private PRESCAB client is optional (`requirements-optional.txt`). | Installed units on existing machines are not affected. |

## Fixes
- One shared database lookup instead of eight copies; one alertlib loader instead of four hard-coded paths.
- `backup.__version__` now matches `module.yaml` (test enforces it).

## Known limits
- SQL migrations still name the original hosts in a few views and seed rows (3.1: host-roles table).
- The DB label `trigkey-agent` remains (3.1 rename).
